## Управление

- Двойной щелчок по `start.cmd` запускает сервисы и открывает браузер.
- `stop.cmd` останавливает это приложение и его контейнеры, сохраняя том базы.
- Из терминала корня проекта:

```powershell
python -B dashboard/deploy/local.py start
python -B dashboard/deploy/local.py status
python -B dashboard/deploy/local.py stop
```

После перезагрузки компьютера достаточно start.cmd. Первый запуск Docker может занять
некоторое время. На форме входа использовать данные созданного вручную аккаунта.
Сеанс завершается после 30 минут бездействия.

Скрипт сначала ожидает доступности Docker именно в Ubuntu/WSL (до 3 минут),
затем запускает сервисы и ожидает ответа дашборда (до 10 минут). Если Docker
пересобирает образы и скачивает библиотеки, запуск может занять несколько минут.
При досрочном завершении запуска выводится код выхода и путь к журналу
`%LOCALAPPDATA%\SoMaA-local\application.log`. Ошибка ожидания сама по себе
не означает потерю данных; не запускайте несколько копий команды одновременно.

## Данные и ограничения

Сгенерирован medium: 430 участников на каждый экзамен, 6 используемых регионов.
Данные загружаются через тестовый API в настоящую PostgreSQL, витрины читаются под
sma_reader, вход/аккаунты — под sma_app. Происхождение явно помечено в интерфейсе.
Живой экран перечитывает БД каждые 30 с; after_appeal — завершенный модельный снимок,
поэтому счетчики сами по себе не изображают текущий экзамен. Replay не включался.

До перехода на bcrypt вход и все восемь маршрутов проверены в Chrome.
После удаления локального аккаунта эти результаты остаются историческими.
У распределения ЕГЭ получены
408 окончательно сдавших; таблицы/графики сравнения, отметок, карты, тем/вариантов
и живого экрана отображаются из БД. Детали — verification.json.
«Аномалии» и «Углубленный анализ» пока сообщают об отсутствии согласованных источников:
модуль расчета аналитика в проекте еще не реализован. Результаты не подменяются ключом
генератора или тестовыми строками. Настройка этих источников — следующий командный этап.
HTTPS и внешний доступ не настраивались: это локальный просмотр на своем компьютере.

## Если изменены файлы в VS Code

Изменения в Windows-копии следует перенести в Linux-копию, затем перезапустить приложение:

```powershell
python -B dashboard/deploy/local.py stop
python -B dashboard/deploy/local.py sync
python -B dashboard/deploy/local.py start
```

sync копирует также `visualization/`, сохраняет существующую `.env`, сгенерированные
данные и локальный кэш `visualization/cache/`. Новые зависимости нужно
отдельно установить в Linux .venv; изменение кода само по себе их не устанавливает.
После перехода на bcrypt процесс дашборда перезапущен отдельно от БД/загрузчика;
его текущий журнал — `/home/dima/SoMaA-local/.local-run/dashboard.log`.
Журнал общего запуска: `%LOCALAPPDATA%\SoMaA-local\application.log`; первичная сборка —
`/home/dima/SoMaA-local-compose.log`. Коммиты и отправка в Git не выполнялись.
