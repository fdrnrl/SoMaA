# Слой чтения дашборда

**Локальный запуск на этом компьютере уже настроен:** http://localhost:8501.
[Инструкция запуска, входа и остановки](deploy/README.md). Ниже — описание реализации.
Для Дмитрия создан новый локальный аккаунт dmitry (admin) с bcrypt.
Данные входа находятся в [локальном файле](.local/credentials.txt), исключенном из Git.

Данные возвращаются как списки словарей, без обязательного импорта pandas/Streamlit.
Режим БД включен по умолчанию. При ошибке БД автоматического перехода на демо нет.

```python
from dashboard.data import read_page

page = read_page(
    ("regions", ("EGE", "OGE"), "02"),
    lambda reader: {
        "regions": reader.region_results(("EGE", "OGE"), "02"),
        "live": reader.live(),
    },
    mode="demo",
)
```

`page["source"]` обязательно показывать вместе с результатами: режим, синтетическое
происхождение, время снимка и ограничения. Демо статическое; время загрузки и результаты
аналитика отсутствуют. Все аналитические методы демо сообщают об отсутствии источника.
Текст о происхождении данных БД также требуется подтвердить с командой.
Для явно синтетической локальной БД задается SMA_DASHBOARD_SYNTHETIC=true:
метаданные и страницы показывают предупреждение о происхождении и ограничениях выводов.

`read_page` кэширует весь результат страницы на 30 секунд, включая все ее фильтры в ключе.
При промахе кэша связанные SQL-запросы выполняются в одном READ ONLY / REPEATABLE READ
снимке. `open_snapshot` дает такой же снимок без кэша. `PAGE_CACHE.clear()` сбрасывает кэш.
Учетные записи и журнал входа через этот кэш не читаются.

Подключение использует настройки `sma.db.connection_settings`, явную роль `sma_reader`,
пароль `SMA_READER_PASSWORD` и тайм-аут 3 секунды. Реальный пароль задается только
окружением/подготовленным `.env`. Согласованные зависимости дашборда закреплены
в корневом `requirements.txt`; схемы и формат данных платформ не меняются.

## Методы

- `filters(exam_type=None, subject_code=None)` — допустимые экзамены, коды предметов и регионы.
- `distribution(exam_type, subject_code, region_code=None)` — балл, число участников, максимум.
- `region_results(exam_types=None, subject_code=None)` — средние по участникам и доли регионов;
  пустой список экзаменов дает пустую выборку, `None` означает все экзамены.
- `live()`, `freshness()` — сводка платформ и состояние загрузок; отсутствие строк не равно нулю.
- `topics(exam_type, subject_code)`, `variants(exam_type, subject_code)` — существующие витрины.
- `anomalies(exam_type=None, subject_code=None)` — все поля 7.2, новые записи первыми.
- `analysis_runs()` — завершенные запуски с параметрами; запуск выбирается явно по договору команды.
- `school_list(run_id, exam_type=None, subject_code=None)` — школы in_list, индекс по убыванию.
- `p1_groups(run_id, exam_type, subject_code, school_code)` — группы выбранной школы/запуска.
- `school_counts(run_id)` — число разных школ в перечне по платформам.

Коды остаются строками, null сохраняется. Decimal преобразуется в float, время остается
с часовым поясом. Для экзаменов 2026 года Москва — UTC+3. Доли 0..1 и проценты 0..100
не преобразуются друг в друга неявно.

## Контракт аналитики для согласования

Имена представлений не придуманы и по умолчанию не заданы. Коллега предоставляет реальные
имена в схеме mart; их можно передать словарем `sources` или переменными окружения:

- `SMA_DASHBOARD_ANOMALIES_VIEW`: 11 полей раздела 7.2.
- `SMA_DASHBOARD_RUNS_VIEW`: run_id, started_at, finished_at, params.
- `SMA_DASHBOARD_SCHOOLS_VIEW`: 19 полей раздела 7.4, включая calculated_at и скорректированные z′.
- `SMA_DASHBOARD_P1_GROUPS_VIEW`: 10 полей раздела 7.3.

Проверяются схема mart и допустимые символы имени. Значения фильтров передаются отдельно
от SQL. Несогласованный источник дает `DataUnavailable` с кодом `source_not_configured`.
Отсутствующий/незавершенный выбранный запуск дает `analysis_missing`; завершенный расчет
без школ дает пустой список. Школы, их группы и счетчики читаются с одним выбранным run_id.
Смысл calculated_at и область каждого запуска остаются предметом согласования с коллегами.

Отбор pending для тем/вариантов еще не согласован. SQL читает существующие витрины без
подмены их определения. Демо считает темы/варианты на готовом after_appeal; если в другом
снимке есть finished+pending, эти методы сообщают `policy_not_agreed`. Основные итоговые
графики всегда используют finished + final/appeal_changed. `diff_from_others` остается
отклонением от среднего остальных; на странице порог 15 п. п. нужно проверять по разнице
максимальной и минимальной долей между вариантами, а не по этому полю.

## Проверка без БД

```bash
python -B -m unittest discover -s tests/dashboard -p test_dashboard_data.py
```

Проверки с подставным соединением подтверждают договор запросов, но не выполнение SQL
в PostgreSQL. Реальная интеграция, права роли и скорость на целевом стенде проверяются
отдельно после подготовки БД. Полный pytest сейчас не требуется для этих автономных тестов.

## Вход и учетные записи

`auth.py` использует существующие app.users/app.login_log под явной ролью sma_app,
пароль берется из SMA_APP_PASSWORD через подготовленное окружение. Схемы проекта
не изменены; bcrypt==5.0.0 добавлен в requirements.txt по поручению Дмитрия.
Рабочий вход требует PostgreSQL; демонстрационный режим данных
самостоятельного входа или регистрации не предоставляет.

Пароли хешируются bcrypt с cost=12 и индивидуальной случайной солью библиотеки.
Новые хеши имеют стандартный формат `$2b$12$...`; проверка выполняется bcrypt.checkpw.
Поддерживаются стандартные префиксы $2a$/$2b$/$2y$ и cost от 4 до 16; ограничение
стоимости проверки защищает от чрезмерно дорогих значений в поврежденном хеше.
PBKDF2 и неизвестные форматы отклоняются. Это соответствует выбору bcrypt в разделе
«Способы выполнения отдельных требований» ТЗ v0.4; NFR-05 требует необратимого
хеширования с индивидуальной солью. Автоматической миграции старых хешей нет.
На отдельном локальном стенде единственный старый аккаунт удален по поручению Дмитрия.
На других стендах перед обновлением нужно проверить наличие аккаунтов старого формата.

Новый пароль: от 10 символов, буквы и цифры, максимум 72 байта UTF-8.
Более длинный пароль отклоняется без обрезания; для кириллицы число символов меньше 72.
Ограничение библиотеки описано в [документации bcrypt](https://pypi.org/project/bcrypt/).
Логин: 1–128 печатных символов,
пробелы по краям убираются. Исходный пароль в БД и журнал не записывается. Поля пароля
форм очищаются после отправки. Неизвестный логин, неверный пароль и блокировка дают
одинаковое сообщение отказа.

Пять ошибок подряд блокируют вход на 15 минут; после истечения блокировки счетчик
начинается заново, успешный вход его обнуляет. Пользовательская строка читается FOR UPDATE;
счетчик и журнал каждой попытки фиксируются одной транзакцией. При отказе записи журнала
сеанс не создается. Административные действия повторно проверяют роль в транзакции.
Администратор создает staff/admin, блокирует и разблокирует записи; себя блокировать нельзя.
Парольные хеши не входят в таблицу пользователей, показываемую в интерфейсе.

Сеанс хранится на сервере в Streamlit Session State. Срок бездействия — 30 минут;
явные действия вызывают `AuthService.touch` или `ui.user_activity` как callback.
Обычный rerun и автоматическое обновление live активность не продлевают. Watchdog
проверяет сеанс каждые 15 секунд и возвращает страницу входа после истечения срока.
Роль, блокировка и изменение хеша перепроверяются по БД; при ее отказе доступ закрывается.
Перезагрузка соединения браузера со Streamlit может потребовать нового входа.

`app.py` до входа регистрирует только страницу входа через st.navigation. После входа
сотруднику доступны главная и восемь рабочих страниц, администратору также управление
пользователями. Каждая страница вызывает `ui.require_user()` до чтения и показа данных;
административная — `ui.require_user("admin")`.
Нужен Streamlit с API st.Page/st.navigation/st.fragment (1.37+); версия 1.67.0
закреплена в корневом requirements.txt. AppTest/Chrome проверены; локальное развертывание
и вход через настоящую БД описаны в deploy/README.md. Полная приемка командного стенда
остается отдельной задачей.

### Первый администратор

После подготовки БД и SMA_APP_PASSWORD тимлид запускает из корня проекта в активном
окружении интерактивного терминала:

```bash
python -X utf8 -B -m dashboard.manage_users bootstrap-admin --login admin
```

Пароль вводится дважды скрытым вводом; параметра пароля в командной строке нет.
Команда отказывается работать без интерактивного терминала и при уже существующем
администраторе. Проверка и вставка защищены блокировкой таблицы app.users в транзакции.
Старый аккаунт PBKDF2 и прежние файлы с его логином/паролем удалены.
По новому поручению Дмитрия создан dmitry (admin) с bcrypt; данные сохранены только
в dashboard/.local/credentials.txt рабочей Windows-копии. По поручению Дмитрия пользователи Windows могут читать папку и файл; изменять файл может текущий пользователь. dashboard/.gitignore исключает .local/ из Git,
а prepare_runtime.py пропускает ее при копировании на Linux-диск.
Автоматического создания аккаунта при запуске приложения нет. На пустом стенде
первый администратор создается указанной выше интерактивной командой.
Для браузера тимлиду нужно настроить HTTPS/TLS; обычный HTTP не закрывает NFR-11/T-31.

Все автономные тесты дашборда:

```bash
python -B -m unittest discover -s tests/dashboard -p 'test_*.py'
```

Проверки форм используют подставной Streamlit, проверки транзакций — подставное соединение.
Они не заменяют прогон с настоящими PostgreSQL и браузером на подготовленном стенде.

## Рабочие страницы (раздел 5 плана)

После подготовки окружения и администратора запуск из корня:

```bash
python -m streamlit run dashboard/app.py
```

В боковой панели источник выбирается явно: БД по умолчанию или статический
синтетический снимок. Оба режима требуют обычного входа. Тестовые учетные записи
AppTest находятся только в tests/dashboard и не включаются командой запуска приложения.

- «Распределение»: экзамен/предмет/регион в одной строке; карточки числа участников,
  среднего балла, медианы и моды. Статистика рассчитывается по частотам участников,
  без развертывания списка работ. При четном числе участников медиана — среднее двух
  центральных результатов. Все моды сохраняются; при одинаковых частотах разных баллов
  выраженной моды нет. На графике отмечены среднее и медиана, при совпадении — одной
  общей линией с подписью. Таблица частот сохранена и имеет русские заголовки.
  Переключатель вида добавляет накопленную долю участников с баллом не выше указанного.
- «Сравнение экзаменов»: выбранные платформы на одном графике. При нескольких предметах
  региональный mean_pct объединяется с весами participants; пропуск не превращается в ноль.
  По умолчанию показана тепловая карта «регион × экзамен»; доступны также столбцы.
- «Отметки»: только ОГЭ/ВПР, share_grade2 из источника, без повторного расчета grade.
- «Регионы»: настоящие контуры, окраска mean_score, серый цвет отсутствующих значений.
  [Источник, дата и ограничения геометрии](assets/README.md). Сопоставлены 20 кодов
  тестового справочника; неизвестные коды остаются в таблице и дают предупреждение.
  Переключатель «Рейтинг» показывает среднее выполнение, число участников и взвешенное
  среднее всей выбранной группы. Рейтинг работает и для кодов без геометрии.
- «Темы и варианты»: год/раздел/код/уровень, доли баллов по вариантам каждого задания.
  Пометка строго при max(share_score) − min(share_score) > 0,15, минимум два варианта.
  Отсутствие КИМ и отсутствие проверенных ответов имеют отдельные сообщения. Пункт 09
  остается открытым; определения общих витрин самостоятельно не менялись.
  Варианты показаны тепловой картой «вариант × задание» с переключением на столбцы.
  Отметка разницы учитывает все варианты, включая другие части графика.
- «Живой экран»: сводки четырех платформ, А1–А3, выбранный завершенный расчет школ,
  время сводки/загрузки, свежесть по источникам. Записи с ранее не встречавшимися ID
  поднимаются наверх с цветом и словом «НОВАЯ»; первое чтение задает базовую линию.
  Изменение detected_at при том же ID не создает новую запись. Автообновление каждые
  30 с не вызывает callback активности, проверка доступа выполняется при каждом обновлении.
  Задержка строго >120 с дает предупреждение в режиме БД. Демо не проверяет живую загрузку.
  Добавлены составные столбцы состояний работ и диаграмма задержек источников с порогом
  120 с. Неполная сводка платформы не подменяется нулевыми количествами.
- «Аномалии»: все 11 полей, все сохраненные строки; кнопка «Выгрузить» сохраняет CSV.
- «Углубленный анализ»: явный выбор завершенного run_id, его время и параметры,
  фильтры экзамена/предмета, 19 полей школ в порядке индекса и 10 полей групп П1.
  Школа определяется сочетанием экзамен/предмет/код; группы читаются с тем же run_id
  и тем же снимком, что показанный перечень. Фильтры перечня не зависят от наличия
  сессий этого расчета в текущем наборе. Пустой завершенный перечень отличается от
  отсутствующего расчета/источника. Кнопка «Выгрузить» сохраняет текущий перечень школ.
  Нет результата для платформы — «—», а не ложный ноль.

Источник аналитики должен сохранять стабильный anomaly_id и неизменяемые результаты
завершенного run_id. Если коллега обновляет уже завершенные расчеты, требуется согласовать
версионирование. Область запуска видна в params; выбирать подходящий запуск нужно явно.
Текущий school_counts возвращает только платформы с найденными школами. Различить
нулевой результат и платформу вне области расчета без согласованного контракта нельзя:
отсутствующая строка показывается как «—».

### Новые наборы данных и размеры графиков

Новые графики строятся из текущих результатов запросов, без привязки к конкретным
регионам, заданиям, вариантам и числам тестового набора. Требуются существующие
контракты mart: те же поля, типы и единицы. Новый набор должен быть загружен обычным
пайплайном, а материализованные витрины — обновлены. Само добавление файла в папку
репозитория не подключает его к БД; режим демо остается отдельным статическим снимком.

Большие списки регионов, вариантов, заданий и источников разделены на части по 20
элементов с выбором части графика. Таблицы сохраняют полный результат текущих фильтров.
Части не меняют среднее-ориентир рейтинга и проверку разницы вариантов. Длинные подписи
переносятся и сокращаются; полные названия остаются в таблицах.

На тепловых картах ноль — измеренное значение, серый цвет/«—» — отсутствующее.
Для варианта без участников ячейка не считается измеренным нулем. Цвет текста выбирается
по контрасту с фоном. Шкалы процентов фиксированы 0–100, количества и задержки имеют
динамический диапазон. Временные ряды и результаты аналитики не выдумываются.

Ранее проверены настоящий Streamlit AppTest 1.67.0 и matplotlib 3.11.2 под Python 3.13.7
во временной папке, без подключения PostgreSQL.
AppTest проверяет выполнение UI, но не размеры окна, браузерный рендеринг или таймер
в реальном времени. Для AppTest нужны обе библиотеки; без них соответствующие тесты
явно пропускаются, основные проверки работают на стандартной библиотеке.

## Оформление и навигация

Общие стили находятся в `theme.css`, заголовки и описания страниц — в `ui.py`.
Главная содержит восемь карточек с нативными `st.page_link`: переходы сохраняют
сеанс и используют те же зарегистрированные защищенные страницы. В боковом меню
выделены результаты экзаменов, мониторинг и анализ; управление пользователями
отображается только администратору.

Фильтры собраны в компактные строки, показатели — в карточки, вид графика выбирается
кнопками с сохранением нативного управления с клавиатуры. Подробности источника
и параметры расчета раскрываются по запросу; предупреждения о синтетике остаются
видимыми. «Экран обновлен» на живой странице означает время перерисовки, а не
время загрузки платформы: последнее по-прежнему показано отдельно.

Локальный `deploy/start.sh` задает светлую тему с синим акцентом. Оформление также
проверено на контрольных страницах с темной темой. CSS не подключает внешние
шрифты или изображения. Цвета и сетки matplotlib едины для всех графиков;
запросы, единицы, фильтры окончательных результатов и форматы CSV не менялись.

## CSV (раздел 6 плана)

Общий сериализатор — `dashboard.export.csv_bytes`; `anomalies_csv` и `schools_csv`
фиксируют порядок 11/19 полей из разделов 7.2/7.4. Кодировка UTF-8 без BOM,
разделитель `;`, десятичная запятая, заголовок первой строкой, окончания строк CRLF.
Кавычки, разделители и переносы внутри полей экранирует стандартный csv.writer.
Списки внутри поля соединяются запятой; логические значения — true/false, null — пустое
поле. Время — ISO 8601 с +03:00 (Москва). Время без часового пояса отклоняется.
Числа не округляются при экспорте; очень малые p-значения не превращаются в ноль.
Коды остаются строками с ведущими нулями, расчетные показатели и скорректированные z′
берутся из показанных строк без пересчета. CSV не задает типы столбцов: при импорте
в таблицы коды следует читать как текст.

«Аномалии» выгружает все показанные записи. «Углубленный анализ» выгружает весь
отфильтрованный перечень выбранного завершенного run_id; выбор одной школы для П1
не сужает CSV до этой школы. Имя файла содержит run_id, экзамен и предмет, `all`
означает отсутствие соответствующего фильтра. В режиме синтетики добавляется префикс
`demo_`; состав обязательных столбцов сохраняется. Пустой успешный результат дает
файл с заголовком. При недоступном источнике или отсутствии выбранного завершенного
расчета файл не предлагается. Кнопка требует защищенной страницы, явное нажатие
учитывается как действие пользователя с повторной проверкой сеанса.

Проверки формата и связи CSV с показанной выборкой:

```bash
python -B -m unittest discover -s tests/dashboard -p test_export.py
```

Кнопки и передаваемые им CSV также проверяются настоящим Streamlit AppTest.
Открытие скачанного файла в Яндекс Таблицах (пункт 65) еще не проверено.
