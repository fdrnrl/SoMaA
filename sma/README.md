# Модуль аналитика аномалий СМА (ТЗ v0.4)

Моя зона по ТЗ (табл. 4): **правила А1–А3, углубленный анализ (П1–П4, индекс аномальности, перечень школ) и их автотесты**.
Данные синтетические; выводы ограничены свойствами генератора (NFR-30).

## Что делает модуль, простыми словами
Берет данные экзамена (сессии, ответы, события прокторинга) и ищет подозрительное:

| Код | Что ищет | Откуда в ТЗ |
| --- | --- | --- |
| А1 | школа, у которой средний балл выше среднего по школам региона более чем на 2σ | FR-07, FR-08 |
| А2 | 5+ участников одной школы и варианта с одинаковыми ответами на всю часть 1 | FR-09 |
| А3 | участник с 3+ событиями прокторинга (tab_switch, copy, paste, fullscreen_exit) | FR-10 |
| П1 | пары участников одной аудитории с совпадающими *редкими неверными* ответами → группы | FR-34–FR-37 |
| П2 | «ошибки Гуттмана»: легкие задания неверно, трудные верно | FR-38 |
| П3 | школа решает трудные задания лучше региона, а легкие — как регион | FR-39 |
| П4а / П4б | слишком малый разброс баллов / слишком много баллов сразу над порогом | FR-40, FR-41 |
| индекс | среднее скорректированных z-оценок П1–П4 → перечень школ для проверки | FR-42–FR-44 |

## Запуск
```bash
pip install -r requirements.txt
python -m sma_anomalies Тестовые_данные_СМА_v2/medium out/        # считает все 4 платформы, пишет CSV
python -m sma_anomalies.check_key Тестовые_данные_СМА_v2/medium   # сверка с ключом набора (T-63)
python tests/run_tests.py            # все тесты одной командой (или просто: pytest -q)
```
Тестам интеграции нужен набор: `SMA_DATA=путь/к/Тестовые_данные_СМА_v2` (по умолчанию ищется в текущей папке; нет набора — тесты пропускаются).

Результат запуска (`results/medium`, `results/small`): `anomalies.csv` (раздел 7.2), `schools.csv` (7.4), `groups.csv` (7.3),
`details.csv` (состав групп А2), `run-log.jsonl` (журнал запуска с параметрами таблицы 13, NFR-24).
Формат CSV — по ТЗ: UTF-8, `;`, десятичная запятая, время ISO 8601.

## Структура
```
sma_anomalies/
  params.py      параметры (табл. 13) + опции, которых нет в ТЗ (выключены по умолчанию)
  normalize.py   нормализация ответов (FR-31, FR-32)
  prep.py        окончательные результаты, группа сравнения (аудитория или школа)
  rules.py       А1–А3, запись об аномалии (7.2), защита от дублей (FR-13)
  deep.py        П1–П4, z-оценки, корректировка, индекс, перечень
  runlog.py      планировщик запусков FR-30 (каждые 10 мин + один после конца) и журнал запусков NFR-24
  export.py      CSV 7.2 / 7.3 / 7.4
  analysis.py    запуск по платформе и по набору
  check_key.py   сверка с answer_key.json
tests/           50 тестов: unit, интеграционные, property-based
```

## Входные таблицы (контракт для разработчика пайплайнов)
Модуль читает pandas-таблицы с теми же столбцами, что в JSON формата v2 (после `json_normalize`), — их можно собирать из витрин (раздел 7.6):
`sessions` (participant_id, exam_type, subject_code, variant_id, region_code, school_code, room_code, status, result_status, primary_score, updated_at, deleted),
`answers` (participant_id, task_number, answer, is_correct, deleted), `events` (participant_id, event_type, deleted),
`subjects` (exam_type, subject_code, threshold_score). Удаленные записи отбрасываются; в расчетах — только `finished` и `final`/`appeal_changed`.
Запись результатов в схему `analytics` БД и вызов `Scheduler.tick` по таймеру — на стороне пайплайна/оркестратора: модуль отдает DataFrame и CSV.

## Результаты проверки
* **Ключ набора:** medium — 56 проверок, small — 33, все пройдены: заложенное найдено, ловушки (A2_blank, A3_focus, A3_deleted, deleted_session) не сработали, лишних А1/А3 нет.
* **Эталон (reference_check):** П1–П4, z′ и индексы всех школ четырех платформ совпадают с ключом (расхождение ≤ 0,005 — округление в ключе); группы П1 и число подозрительных пар совпадают (T-52).
* **Тесты:** 50 из 50. Один расчет платформы — около 0,3 с (NFR-22: до 60 с).
* Тесты покрывают T-07–T-14, T-41–T-52, T-54, T-55, T-57, T-63, T-70. T-53 (3 из 100 школ в перечне) и T-56 в этом наборе не проверялись — нужен генератор на 100 школ (см. ниже).

## Решения по неоднозначным местам ТЗ (проверено на эталоне)
1. **σ в А1** — по выборке (ddof = 1). Только так сходятся z из ключа и граница (n−1)/√n из раздела 10 ТЗ. В ТЗ стоит это уточнить.
2. **П1: пары и группы ищутся во всех школах**, а N_min (FR-33) ограничивает школьное значение П1, z и индекс. Иначе не находится заложенная группа в школе 77007 (9 участников) и вся small. Это расходится с буквой T-43.
3. **min_p_value группы — p после поправки Холма** (так в ключе); сырое — в `min_p_raw` внутри таблицы групп. Холм — по всем парам школы.
4. **П2:** задания упорядочены по доле верных, ничьи — по номеру задания (иначе G* ≠ ключ и не гарантируется G* ∈ [0; 1]).
5. **П3:** «задание» — номер задания по всем вариантам (варианты параллельные); медиана — по заданиям региона.
6. **А2:** учитываются только `finished` с полным набором ответов части 1. Идентификатор группы — `школа:вариант:хеш вектора ответов`, поэтому не меняется, если в группу добавится участник.
7. `detected_at`/`calculated_at` по умолчанию — момент снимка данных, а не часы компьютера (воспроизводимость, NFR-23).

## Вопросы к ТЗ (стоит поднять до недели 9 — раздел 10 ТЗ, параметры по T-46/T-53)
* **Перечень школ пуст при параметрах ТЗ** на всех платформах medium: максимальный индекс 0,40–0,61 при И_min = 2,0. Причина — среднее z′ пяти показателей, из которых П1 почти всегда 0 (MAD = 0), плюс множитель n/(n+K) ≈ 0,35 для школы из 12. **T-53 не пройдет.** Проверено опциями `Params(index_agg="max")`: И_min = 2,0 → 3 из 12 заложенных П3/П4 школ, И_min = 1,5 → 6 из 12, ложных 0. Нужно решение: максимум вместо среднего и/или меньшие И_min и K.
* **А1 в регионе из 5 школ не сработает никогда** (z ≤ 1,79) — известное ограничение; вариант `Params(a1_sigma_mode="leave_one_out")` считает σ без проверяемой школы.
* **FR-33 и T-43 против П1 на малых школах** — см. п. 2 выше.
* **FR-66** (различие вариантов) в моей зоне нет — это витрина и страница «Темы и варианты»; на small оно шумит (README набора, наблюдение 4).
